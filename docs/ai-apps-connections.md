# Conexões de aplicativos no Studio

A central **Aplicativos** permite autorizar Google Agenda, Gmail, Google Drive, Google Tasks, Google Docs, Google Sheets, Google Slides, GitHub e Notion quando os clientes OAuth do servidor estão configurados. A opção de leitura é aplicada também pelo Dialogy. No GitHub, o escopo `repo` solicitado ao provedor inclui escrita; a restrição de leitura é local. As páginas e capacidades do Notion são escolhidas no provedor. OAuth exige URLs de retorno e credenciais registradas em cada serviço; consulte `.env.example`. Uma conexão autorizada deve ser vinculada a um procedimento ou conector publicado.

Docs, Sheets e Slides têm consentimento separado, limitado à origem de API de cada aplicativo; a autorização do Drive não substitui essas conexões. Habilite as APIs correspondentes no projeto Google Cloud. Os modelos permitem ler, criar e acrescentar texto a documentos; criar planilhas e ler ou substituir valores de intervalos A1 usando `RAW`; e criar ou ler apresentações, adicionar slides em branco e caixas de texto. Escritas exigem aprovação. Intervalos de planilha aceitam nomes simples de abas e endereços A1; recursos de formatação, edição rica e todas as funções desses serviços não estão cobertos. A disponibilidade exige permissões sobre os arquivos e depende dos escopos concedidos. Consulte as APIs oficiais de [Docs](https://developers.google.com/workspace/docs/api/reference/rest/v1/documents), [Sheets](https://developers.google.com/workspace/sheets/api/reference/rest) e [Slides](https://developers.google.com/workspace/slides/api/reference/rest).

Para consultar disponibilidade na Agenda, o consentimento inclui o escopo de disponibilidade além do escopo de eventos. Conexões anteriores à adição desse escopo precisam ser autorizadas novamente. Remarcar e excluir eventos exigem acesso de escrita e aprovação.

Para Slack, Microsoft Graph (Outlook, OneDrive e Teams), Trello, Asana, GitLab, Linear e Jira, a biblioteca de conectores do editor de automações oferece operações prontas como rascunhos. O administrador deve obter e cadastrar no cofre Nexus uma credencial autorizada, selecionar a operação, vincular a credencial, revisar os argumentos e publicar a versão. Esses serviços ainda não têm consentimento OAuth integrado na central. As operações prontas não representam cobertura completa de cada API.

- **Slack:** token autorizado para o canal e os escopos necessários. A API pode retornar erros no corpo mesmo com HTTP 200; os conectores verificam `ok`.
- **Microsoft Graph:** use uma credencial OAuth com a origem `https://graph.microsoft.com` e permissões para a operação; os modelos `/me` exigem acesso delegado a um usuário, e algumas ações exigem consentimento administrativo. `sendMail` retorna aceitação para processamento, não confirmação de entrega. Criar uma conversa no Teams não envia mensagem.
- **Trello:** use uma credencial OAuth 2.0 autorizada ou cadastre no cofre o cabeçalho `Authorization` no formato `OAuth oauth_consumer_key="...", oauth_token="..."`; não inclua chaves ou tokens na URL do conector.
- **Asana e GitLab:** use token ou OAuth com permissões adequadas; altere o host do GitLab apenas quando utilizar uma instância própria confiável.
- **Linear:** token OAuth Bearer ou chave pessoal no cabeçalho `Authorization`, conforme a forma de autenticação escolhida. As operações GraphQL inspecionam erros retornados no corpo. A consulta de equipes também pede aprovação, pois usa POST.
- **Jira Cloud:** substitua `your-domain.atlassian.net` pelo host verdadeiro do site antes de publicar, e configure a credencial correspondente, como autenticação básica com e-mail e token de API. OAuth 3LO da Atlassian usa outro endereço e requer configuração própria. Os campos exigidos na criação de uma issue variam conforme o projeto.

As operações prontas que criam ou enviam dados exigem aprovação humana. Limites de acesso do provedor, compartilhamento de páginas/arquivos e escopos continuam sendo necessários; executar testes locais com mocks não confirma que uma conta externa está conectada.

Referências: [Slack](https://api.slack.com/methods/chat.postMessage), [Microsoft Graph](https://learn.microsoft.com/en-us/graph/api/user-sendmail?view=graph-rest-1.0), [Trello](https://developer.atlassian.com/cloud/trello/guides/rest-api/authorization/), [Asana](https://developers.asana.com/reference/createtask), [GitLab](https://docs.gitlab.com/api/projects/), [Linear](https://linear.app/developers/graphql) e [Jira](https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-issues/).


A biblioteca também inclui operações para Google Tasks, Todoist, ClickUp, Discord, Dropbox, Box, HubSpot, Salesforce, Pipedrive, Shopify, WooCommerce, Nuvemshop, n8n, Make, Vercel e Google Analytics. Somente o Google Tasks tem consentimento nativo nesta lista; os outros exigem credencial previamente autorizada no cofre. Os modelos não oferecem todas as funções do serviço. Nas lojas e no Salesforce, substitua os domínios de exemplo antes de publicar. Para Nuvemshop, informe um contato real no cabeçalho `User-Agent`; para n8n, informe a URL pública da sua instância e o cabeçalho de API adequado; para Make, ajuste a região e use `Authorization: Token ...`. Discord requer credencial de bot ou OAuth adequada, e o relatório Analytics requer o escopo e ID de propriedade corretos. Os modelos de produto Shopify usam a GraphQL Admin API; confirme os escopos da aplicação e a versão configurada.

Os modelos de contatos HubSpot usam a API `2026-09` e token Bearer, com `crm.objects.contacts.read` para consulta e `crm.objects.contacts.write` para criação. Salesforce usa a versão `v68.0` e o domínio da organização; a criação de contas depende das regras e campos obrigatórios da organização. Pipedrive usa a API v2 com OAuth Bearer ou chave no cabeçalho `x-api-token`. WooCommerce usa HTTPS e autenticação Basic com a chave e o segredo da REST API. Nuvemshop usa a Admin API `2025-03`, token Bearer obtido na instalação da loja, ID de loja e `User-Agent` com contato. O produto criado usa `visibility: hidden`; não está disponível para compra até ser publicado. Criação de registros e produtos exige aprovação.

Para Shopify, cadastre no cofre uma credencial de chave de API no cabeçalho `X-Shopify-Access-Token`, com acesso à loja escolhida. A consulta de produtos precisa de `read_products`; a criação de rascunhos precisa de `write_products` e da permissão de criação do usuário. A escrita exige aprovação, e erros retornados pela API em respostas HTTP 200 são tratados como falhas.

Para **Microsoft Word, Excel e PowerPoint**, os modelos usam credencial delegada do Microsoft Graph, com origem `https://graph.microsoft.com`. É possível consultar metadados e baixar arquivos DOCX, XLSX e PPTX do OneDrive para o armazenamento privado do workspace, com limite de 5 MB, para uso pelo leitor de documentos. O download exige acesso `Files.Read` ou superior e segue um único redirecionamento HTTPS público sem encaminhar o token nem expor a URL temporária. Também é possível enviar arquivos privados de até 1 MB para a raiz. O envio requer `Files.ReadWrite`, exige aprovação e **substitui** um arquivo existente com o mesmo nome. As operações Excel também permitem listar abas e ler ou atualizar intervalos A1, usando a permissão delegada `Files.ReadWrite` exigida pelo Graph mesmo para leitura; atualizar requer aprovação. Os modelos não editam diretamente o conteúdo de Word ou PowerPoint pelo Graph. Consulte as referências oficiais de [download no OneDrive](https://learn.microsoft.com/en-us/graph/api/driveitem-get-content), [upload no OneDrive](https://learn.microsoft.com/en-us/graph/api/driveitem-put-content), [leitura de intervalo Excel](https://learn.microsoft.com/en-us/graph/api/range-get?view=graph-rest-1.0) e [atualização de intervalo](https://learn.microsoft.com/en-us/graph/api/range-update?view=graph-rest-1.0).

Referências adicionais: [Google Tasks](https://developers.google.com/workspace/tasks/reference/rest), [Todoist](https://developer.todoist.com/api/v1/), [ClickUp](https://developer.clickup.com/reference/createtask), [Dropbox](https://developers.dropbox.com/en-us/dbx-team-files-guide), [Box](https://developer.box.com/reference/post-folders/), [HubSpot](https://developers.hubspot.com/docs/api/how-to-use-hubspot-api), [Salesforce](https://developer.salesforce.com/docs/platform/api-rest/guide/resources-list.html), [Pipedrive](https://developers.pipedrive.com/docs/api/v1/Persons), [Shopify GraphQL Admin API](https://shopify.dev/docs/api/admin-graphql/latest/mutations/productcreate), [WooCommerce](https://developer.woocommerce.com/docs/apis/rest-api/v3/products), [Nuvemshop](https://tiendanube.github.io/api-documentation/resources/product), [n8n](https://docs.n8n.io/connect/n8n-api/user/), [Make](https://developers.make.com/api-documentation/api-reference/scenarios), [Vercel](https://vercel.com/docs/rest-api) e [Google Analytics](https://developers.google.com/analytics/devguides/reporting/data/v1/basics).

Os conectores de Gmail permitem ler mensagens e responder a uma conversa com destinatário, texto, assunto, `threadId` e `Message-ID` revisáveis; a mensagem MIME é construída no servidor e o envio exige aprovação. Os do Drive exportam documentos como texto e a primeira aba de planilhas como CSV. O Notion permite ler propriedades e blocos e acrescentar parágrafos com aprovação. Os do GitHub consultam e criam branches, leem e atualizam arquivos e criam pull requests; atualizações, branches e PRs exigem aprovação. Consulte a branch de origem e use o SHA retornado ao criar a nova.


O modelo **Meta Ads · Consultar desempenho de campanhas** é somente leitura e requer ID numérico da conta de anúncios e token autorizado para consultar a conta, guardado no cofre. Retorna métricas dos últimos sete dias; a disponibilidade depende das permissões e do acesso concedido à conta. A estrutura de contas e insights está descrita no [SDK oficial da Meta](https://github.com/meta/facebook-python-business-sdk/blob/main/examples/async.py).

No **WhatsApp Business**, a conexão oficial existente usa o tipo `wa_cloud` e o fluxo da API oficial Meta por meio da instância Evolution; conexões por QR Code são outro tipo de canal. A ferramenta **Ler conversa WhatsApp Business** consulta até 20 mensagens anteriores da conversa atual, no mesmo workspace e sem notas internas. A ferramenta **Responder WhatsApp Business** pode ser anexada ao agente e prepara uma resposta de até 4.096 caracteres apenas para a conversa e a instância oficiais que originaram o atendimento. A mensagem, destinatário e instância são apresentados para aprovação humana antes do envio; a instância e a janela de 24 horas são verificadas novamente. Uma tentativa cujo resultado seja incerto não é reenviada automaticamente. A ferramenta não inicia conversas, não escolhe outros destinatários nem envia templates fora da janela; consentimento para mensagens proativas e os templates aprovados continuam sendo tratados pelos fluxos próprios do canal. A confirmação do provedor indica aceite, não garante entrega ou leitura.

Os resultados de integrações podem ser lembrados por contato e agente enquanto a mesma conexão continuar autorizada. A lista mostra uma prévia; quando houver `content.id`, o agente pode recuperar o JSON redigido em páginas de até 3.000 caracteres usando `contentId` e `page`. Os blocos são cifrados individualmente e excluídos em cascata com a memória. Para habilitar, aplique também a migração `20261104132000_studio_tool_memory_content` após as migrações anteriores de memória. A resposta completa é limitada a 12 MB serializados, 5.000 páginas, 250.000 nós e profundidade 80; respostas acima desses limites não são salvas integralmente, e o agente recebe um aviso sem repetir a operação. Segredos em campos reconhecidos e campos marcados como sensíveis são redigidos; não é possível reconhecer todos os segredos arbitrários em texto livre. Respostas anteriores a essa migração que só foram guardadas como prévia não podem ser reconstruídas retroativamente. A memória contém apenas os dados que o conector efetivamente recebeu e expôs, não páginas adicionais que a API ainda não retornou.
